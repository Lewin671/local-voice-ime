Design spec · v1

Local Voice IME: keyboard and dictation

A keyboard where speaking is as close as typing. The space bar is the microphone, what you say appears in the text field as you say it, and the screen always shows that recognition happens on the phone.

Principles

Text goes where text lives

Live dictation is written straight into the text field, underlined until final. No transcript bubbles to read and then re-read.

One gesture, one meaning

Hold space to talk, release to insert, slide up to discard. Tap the mic to talk hands-free. Nothing else starts the microphone.

Privacy is visible

While the microphone is on, a lock and the words "On-device" stay on screen. The microphone never stays open after 10 s of silence. The app goes online only after a tap on a button that says what is fetched and from where: a speech model, or a new version of the app.

Quiet surface, one accent

Neutral keys, generous radius, a single teal used only for the things that act: enter, the microphone, the waveform.

Screens

Each state in the light and dark theme. The keyboard follows the system theme; 1 px here equals 1 dp.

Settings: voice input

One screen, Settings → Voice input, holds everything about speech: what stays on the phone, which models are on it, and their downloads. No speech model is part of the installed app, so the first visit here is to download the standard one (240 MB); the high-accuracy one is optional. It is a list like the rest of the settings; only the model row is new.

Rules: the app never goes online by itself. A download starts with a tap on Download or Resume and at no other time. What was downloaded is never fetched twice: pausing, losing the connection or leaving the app keeps it. A model is used only after every file matched its pinned checksum. Both models are rows of the same kind and behave alike. The standard model is the one voice input cannot do without: its row says "Needed for voice input", and deleting it says that voice input stops until it is downloaded again. The refinement switch is disabled until the high-accuracy model is installed. A further downloadable model is one more row of the same kind.

Settings: app update

The app is installed from a file, not from a store, so it brings its own way to get a newer one: Settings → App update, a destination in the main settings list. The app does not look for updates by itself, not at start-up and not in the background; the screen asks github.com when Check for updates is tapped and at no other time. A new version is a row of the same kind as a speech model, with one more step at the end: Android installs it.

Rules: the check is one request to github.com for the newest release of this project; it carries no identifier and nothing about the phone. What it found is remembered, so the new version is still listed when the screen is opened again; nothing else is, and there is no badge, notification or reminder anywhere else. The package is fetched from the same release and must match the checksum published with it. Install hands the file to Android, which asks for confirmation (the first time also whether this app may install apps) and accepts the package only if it is signed with the same key as the installed app. Declining is not an error: the row stays at "Downloaded and verified". Speech models and settings are kept. While Android replaces the app the keyboard is gone for a few seconds; afterwards the downloaded file is deleted and the screen shows the new version as installed.

Interaction

You doThe keyboard doesEnds when
Hold spaceAfter the long-press delay: tick, keys fade to the listening surface, microphone starts. Speech appears underlined in the text field, without closing punctuation until it is final. If the speech model is not in memory yet, the status reads "Getting ready. Keep talking" and nothing said meanwhile is lost.You release: remaining speech is recognized and inserted. Keys return.
Slide up while holdingCrossing the cancel line turns the hint and waveform red: "Release to cancel".Release above the line: nothing is inserted, the preview is removed. Slide back down to keep talking.
Tap the microphone pillTick; the toolbar becomes the dictation strip (lock, level trace, Stop) and the microphone starts. The keyboard stays as it is. What you said is inserted when you pause, without a full stop yet: go on within 4 s and it stays one sentence, punctuated as a whole; the full stop follows once you have stopped for longer.You tap Stop, type a letter, open another panel (emoji, clipboard, text editing), hide the keyboard, the field loses focus, or 10 s pass without speech (the strip then reads "Off after 10 s of silence" for 4 s).
Tap punctuation, a digit, space, ⌫ or ↵ while dictatingThe key does what it always does and dictation goes on. The sentence ends where it stands, without a full stop: you are punctuating by hand. Text typed while an utterance is still underlined is inserted after that utterance, once it is final. ⌫ deletes one character, always.
Type a letter while dictatingTyping takes over: the microphone turns off, what was said is written first, then the letter is typed and candidates appear as usual. The pill is back to "Speak" for the next time.
Hold space while dictatingNothing: the microphone is already on.
(High-accuracy model installed) nothingAfter each utterance is inserted, a larger model transcribes the same audio again. Words that differ are replaced in place; punctuation, digits and capitalisation stay as inserted. Once the microphone is off, the pill reads "Refining…" until this is done.Skipped silently if the text was edited or the cursor moved in the meantime: refinement never touches text it did not write.
Move the cursor while dictatingDictation stops. The words shown so far stay where they were; nothing is written at the new position.
Short tap on spaceInserts a space or picks the first candidate, as on any keyboard.

The microphone pill and hold-to-talk are absent on password fields. Undo is offered after hold-to-talk only: after hands-free dictation the pill is the way to go on speaking, and a tap there must never remove text. If the speech model has not been downloaded, the pill and the space bar look as usual, and both show the strip, which says what is missing and offers one button that opens Settings → Voice input; the keyboard itself never starts a download. If microphone access is missing, the strip says so and offers one button to grant it. Back at the keyboard with the missing thing in place, listening starts; without it, the strip is gone. Any key dismisses a strip that only has something to say. Errors name their cause and stay for 4 s: "Another app is using the microphone", "Could not load the speech model".

Accepting an implementation

A build matches this spec when scripts/ui-shots.sh produces screenshots of every state above in both themes and each one agrees with its drawing on: what is visible, where it sits, which element carries the accent, and the wording. Pixel offsets under 2 dp are not defects. Wording here is the source for values/strings.xml.
